# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

Bilingual (English / Korean) study materials for **AP World History: Modern**, built to the College Board CED and then revised against the class textbook. There is no code, build, or test suite. Every deliverable is a Markdown or OPML file under `Unit<N>/`, and each English file has a Korean twin. The user writes requests in Korean; reply in Korean. `.enchante-tool-results/` is generated by the host app; ignore it.

## File families

Files are grouped by unit, then by kind: `Unit<N>/{Notes,Summaries,Flashcards,Mindmaps,Tests}/`. File names keep the `AP_WH_` prefix.

| Path | What it is |
|---|---|
| `Unit<N>/Notes/AP_WH_<topic>_Notes_{EN,KR}.md` | Topic notes (e.g. `1.3`) |
| `Unit<N>/Summaries/AP_WH_<topic>_Summary_{EN,KR}.md` | Plain-language summary of a topic's notes (about 100 lines; brief `tools/briefs/6_topic_summary.md`). Unit 1 only so far |
| `Unit<N>/Notes/AP_WH_Unit<N>_CED_{EN,KR}.md` | CED reference for the unit (Units 1–9): per topic, the suggested skill, LOs, HDs with KC codes, and illustrative examples, verbatim. KR keeps the English and adds a Korean line under each item |
| `Course/AP_WH_Course_Exam_Overview_{EN,KR}.md` | Exam format and unit weightings, skills, reasoning processes, themes, course at a glance, and SAQ/DBQ/LEQ rubrics, from the CED |
| `Unit<N>/Flashcards/AP_WH_<topic>_Flashcards_{EN,KR}.md` | 20–40 cards per topic |
| `Unit<N>/Mindmaps/AP_WH_Unit<N>_MindMap_{EN,KR}.opml` | Unit mind map: region → People / Events / Institutions |
| `Unit<N>/Tests/AP_WH_Unit<N>_MCQ_{EN,KR}.md` | MCQ question sheet (KR version: English original + Korean translation under each line) |
| `Unit<N>/Tests/AP_WH_Unit<N>_MCQ_Answers_{EN,KR}.md` | Answer key, explanations, distribution and scoring tables |

Units 1 and 2 are complete. When creating a new unit, copy the structure of the existing files of the same family instead of inventing a new layout.

Units 6–9 have only their CED reference files so far.

Units 3–5 were made elsewhere and copied in. They do not follow the conventions in this file: their headers, source lines, and test formats differ (Unit 3 adds DBQs and practice questions; Unit 4 has a single-language MCQ sheet and `_Explanations` files; Unit 5 has a 100-question test with an answer key). Do not treat them as templates.

`Inbox/` is a gitignored drop folder for incoming material. The user copies files in; sort them into `Unit<N>/` by file name.

**Generated output goes in `Output/`** (gitignored), never next to the source files. This covers PDFs, HTML, images, and any other export or render. Mirror the source path: `Unit1/Notes/X.md` → `Output/Unit1/Notes/X.pdf`. For PDFs, use the `md-to-pdf` skill (`.claude/skills/md-to-pdf/`). The Markdown, OPML, and generator data in `Unit<N>/` and `tools/` are source, not output.

A topic goes through two stages, and the source line at the top of each file records which stage it is in. Use these strings exactly:

After textbook integration, the Focus Question becomes `**Focus Question (textbook Essential Question):**` / `**Focus Question (교재 Essential Question):**`, and the Big Picture opens with the textbook's opening quote.

## Conventions that span multiple files

- **EN/KR parity is a hard rule.** Both files must have the same headings in the same order, the same table row counts, the same Mermaid blocks, the same ⚠️ notes, and the same cards or questions in the same order. In Korean text, key terms and people's names carry the English in parentheses on first use and in tables: `징세 청부 (Tax farming)`, `악바르 (Akbar)`. Korean prose uses plain declarative style (`~했다/~이다`).
- **Textbook vs. scholarship conflicts.** Give the textbook version, then the other view. Each file family has its own wording:
  - Notes: `> ⚠️ The textbook … Many accounts say … Check how your teacher presents this.` / `> ⚠️ 교재는 … 많은 설명에서는 … 선생님이 어떻게 가르치는지 확인이 필요하다.`
  - Flashcards: inline `The textbook says …; many accounts say …` / `교재는 …라고 쓴다. 많은 설명에서는 …라고 본다.`
  - Mind maps: `(⚠️ textbook; most sources say …)` / `(⚠️ 교재 기준, 많은 자료는 …)`
  - MCQ: 📌 marks an explanation that uses content not found in the notes.
- **Notes order:** title → Focus Question → source line → Unit line → LO table → HD table (with a "Covered in / 다루는 곳" § column; every HD and illustrative example must be mapped) → Big Picture (paragraph + flowchart) → §-numbered sections → Timeline (Mermaid `timeline` for events plus `gantt` for periods) → map-style `flowchart` → comparison tables (optionally a `mindmap`) → Key Terms table (Theme | Term | Definition).
- **Mermaid safety rules** (the `md-to-pdf` skill draws every diagram and reports the blocks that fail to parse; as of this writing all of them parse): put node labels and edge labels (`-->|"…"|`) in double quotes, since an unquoted label containing parentheses breaks the diagram, and use `<br/>` for line breaks; no colons inside `timeline` event text (`1279 : A : B` is the valid way to list two events); in `gantt`, use `dateFormat YYYY` with 4-digit years ≥ 1000 only, and put the real earlier start year in the label; no brackets or parentheses in `mindmap` nodes except the root `((…))`; flashcard charts use `pie showData`.
- **Flashcards:** five sections in this order: Key Terms / People / Dates & Events / Cause & Effect / Comparison & AP Writing (핵심 용어 / 인물 / 연도·사건 / 원인·결과 / 비교·AP 서술형). Each card is `- [ ] **Question**` followed by `<details><summary>▶ Answer</summary>…</details>` (KR uses `▶ 정답`). AP writing cards are Claim → Evidence → Reasoning (주장 → 근거 → 설명), each on its own line ending in `<br/>`. The pie counts and the "(N cards)" title must match the real card counts. Explanations must not refer to option letters.
- **MCQ:** stimulus sets of 2–4 questions; A–D options with exactly one correct answer, and never "all/none of the above". A primary source must be a short public-domain excerpt with author, date, and translator. Invented passages, maps, and images must be labeled as written for practice. Tags use the AP skills (Skill 1–5; Skill 5 is split into Causation / Comparison / Continuity & Change). Keep the answer letters balanced and free of patterns, and don't let the correct option usually be the longest one.
- **OPML:** version 2.0, UTF-8, entities escaped. Person: `Name (r. YYYY–YYYY) — one-line achievement [1.x]`. Event: `YYYY — event [1.x]`, in chronological order. Every leaf ends with its source-topic tag.

## Workflow and `tools/`

Each unit goes through the same pipeline. The `unit-builder` skill sequences it and reports where a unit stands (`.claude/skills/unit-builder/scripts/status.py <N>`); its `ced_topic.py` prints a topic's CED block for the stage-1 brief, and `mcq_target.py` picks the MCQ answer sequence. Agent briefs for every step are saved as fill-in templates in `tools/briefs/`. Reuse them; don't rewrite them from scratch. `briefs/5_ced_reference_and_audit.md` holds the briefs for transcribing the CED and for auditing a unit's LO/HD tables against it. Use the audit brief before textbook integration whenever a new unit's notes come from memory or from outside the repo.

1. **CED draft** (`briefs/1_notes_ced_draft.md`): run one agent per topic in parallel. Each writes notes and flashcards (EN + KR). The main session supplies the CED LO/HD text in the brief, copied from `Unit<N>/Notes/AP_WH_Unit<N>_CED_EN.md`. Then show the user the topic list and get confirmation before starting.
2. **Textbook integration** (`briefs/2_notes_textbook_integration.md`): run one agent per topic. Afterwards, send the same agent the flashcard follow-up message in that file; it has already read the textbook. If an agent's write is blocked by permissions, do not work around it. Ask the user to approve, then make the edit in the main session.
3. **Mind map** (`briefs/3_mindmap_data.md`): split the regions among about 4 agents. Each writes paired EN/KR JSON for its own regions only. Then build:
   `python3 -I tools/mindmap/build_opml.py tools/mindmap/unit1 Unit1/Mindmaps`
   The data in `tools/mindmap/unit1/` is final. `applied_fix_dates.py` there is only a record of which reign and life dates were filled from outside the notes; do not rerun it.
4. **MCQ** (`briefs/4_mcq_design_and_review.md`): the main session designs the grid and writes `tools/mcq/unit<N>/data_*.py` itself. The answer order lives in `meta.py` (`TARGET`), and `gen.py` moves each correct option to its slot. Generate with:
   `python3 -I tools/mcq/gen.py tools/mcq/unit1 Unit1/Tests`
   Then run a blind review: a fresh agent answers the questions without the key, and any disagreement means that question gets rewritten.

To change a mind map or MCQ, edit the data and regenerate; don't hand-edit the generated files. Both generators reproduce the current Unit 1 files exactly; the OPML differs only in `dateCreated`. Unit 2's mind map and MCQ predate `tools/` and have no source data. Units 3–5 have no source data either; edit their Markdown and OPML directly. For a new unit, add `tools/<kind>/unit<N>/` containing a `meta.json` or `meta.py` modeled on Unit 1's.

## Checks to run after editing

There is no test suite. Run the `check-materials` skill, which does every check below plus the CED and Mermaid checks in one go:

```bash
python3 -I .claude/skills/check-materials/scripts/check.py --unit <N>            # add --render to draw every diagram
```

The snippets below are what it automates; use them only for a one-off look:

```bash
# Flashcards: per-section card counts must equal the pie, EN must equal KR, every <details> closed
python3 -I -c '
import re,sys
for f in sys.argv[1:]:
    s=open(f,encoding="utf-8").read(); secs=re.split(r"^## \d\.",s,flags=re.M)[1:]
    c=[len(re.findall(r"^- \[ \] \*\*",x,re.M)) for x in secs]
    p=[int(v) for v in re.findall(r":\s*(\d+)",re.search(r"pie showData(.*?)```",s,re.S).group(1))]
    print(f,c,p,"OK" if c==p and s.count("<details>")==s.count("</details>")==sum(c) else "MISMATCH")
' Unit1/Flashcards/AP_WH_1.2_Flashcards_EN.md Unit1/Flashcards/AP_WH_1.2_Flashcards_KR.md

# OPML well-formedness
xmllint --noout Unit1/Mindmaps/AP_WH_Unit1_MindMap_EN.opml Unit1/Mindmaps/AP_WH_Unit1_MindMap_KR.opml
```

For notes, compare the EN and KR files: count headings (`^#+ `), table rows (`^\|`), `` ```mermaid `` blocks, and `⚠️`. Also grep for `�`; Korean writes have occasionally produced broken characters.

Don't count Korean strings with `sort | uniq -c`. Under the macOS UTF-8 locale, it merges different Hangul strings: it once reported a nonexistent Unit 2 tag error by folding `(인과관계)` into `(비교)`. Count with Python (`collections.Counter`) or with one `grep -c` per string.

## Git

- **Never commit to `main` directly.** For every set of changes, start from an up-to-date `main` (`git switch main && git pull`), create a feature branch with a short descriptive name, commit there, and push with `git push -u origin <branch>`. The user opens and merges the PRs on GitHub.
- Run `git branch --show-current` before committing. PRs get merged on GitHub between sessions, so the branch you expect may no longer be checked out.
- Commit and push when the user asks. Say which branch the commit landed on.
- Never force-push or rewrite pushed history. To undo a pushed commit, add a revert commit.

- Korean spellings vary between topic notes: 레콘키스타 / 레콩키스타, 칭기즈 칸 / 칭기스 칸, 말라카 / 믈라카, 아인잘루트 / 아인 잘루트. The Unit 1 mind map uses the first form of each pair.
- About 60 reign and life dates in the Unit 1 mind map come from standard references, not from the notes or the textbook.
